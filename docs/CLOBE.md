# Clobe MCP 조회 연결

Clobe에 수집된 사업자·은행 계좌·통장 내역을 조회하고, **Clobe 최신 동기화**로 최근 2개월의 신규 원장 거래·현재 수집 잔액·계획용 은행 출금을 함께 반영하는 연결입니다. **통장·거래 조회**는 읽기만 하며 수동 분류·적용과 카드 청구에 따른 계획 교체도 별도로 사용할 수 있습니다. 기존 Google 시트 **최신 동기화**와 신규 거래만 추가하는 정책은 유지합니다.

조회 원본은 Clobe가 마지막으로 수집한 통장 자료입니다. 버튼을 누르면 Clobe MCP에 조회를 요청하지만 은행 재수집을 직접 시작하지는 않습니다. 은행 실시간 잔액으로 표시하거나 누락 기간의 거래를 추측하지 않습니다. 계좌 자료에 수집시각이 없다면 확인할 수 없는 상태로 안내합니다.

최신 동기화 후 거래·잔액·계획·분석 화면의 공통 자료를 다시 조회합니다. 저장 완료 뒤 화면 조회만 실패한 경우 거래를 재저장하지 않습니다. 제한된 자동 화면 재조회 후에도 실패하면 결과 창의 **화면 자료 재조회**를 사용합니다. 기존 기록과 충돌해 보류된 건수와 신규 미분류 건수는 저장 성공과 구분해 표시합니다.

외화 통장은 제공된 원본 통화 잔액과 원화 환산 잔액만 별도로 표시합니다. 거래 금액의 원본/환산 통화 계약은 확인되지 않아 외화 통장 거래 조회는 지원하지 않습니다. 원화 통장만 날짜별 거래·입출금 합계를 조회하며, 서버도 외화 요청을 422로 거부합니다. 원본에 없는 잔액·합계를 0으로 채우거나 금액에 통화를 임의로 붙이지 않습니다.

## 조회 API

아래 API는 기존 앱 관리자 인증을 요구합니다. 계좌·거래 조회 응답은 `private, no-store`, 인증·상태 응답은 `no-store`를 사용합니다. 조회 결과는 화면 자료이며 기존 재무 Dataset에 합치거나 저장하지 않습니다.

| 경로 | 입력과 동작 |
| --- | --- |
| `GET /api/clobe/accounts` | 승인한 Clobe 계정의 사업자 목록, 계좌별 수집 잔액과 은행 수집 상태 조회 |
| `GET /api/clobe/card-bills` | `startDate`, `endDate`로 결제일·카드별 청구 합계 조회. 양 끝을 포함해 93일 이내 |
| `POST /api/clobe/transactions` | `{companyId, bankAccountId, startDate, endDate, cursor?, size?}`로 원화 통장 내역 조회. 크기는 1~100, 날짜는 양 끝을 포함하며 다음 페이지는 응답 cursor 사용 |
| `POST /api/clobe/connect` | 별도 앱 OAuth 승인 URL 생성. 고정된 앱 Origin만 허용 |
| `GET /api/clobe/callback` | 로그인 관리자·state·쿠키·단일 사용 attempt를 검증해 연결 저장 후 고정 업로드 화면으로 이동 |
| `GET /api/clobe/status` | 비밀값 없는 연결 상태 조회 |

Clobe MCP는 고정 endpoint와 조회 도구 `get_my_context`, `get_bank_accounts`, `get_labeled_transactions`, `get_scraping_status`, `get_labeled_card_billing_items`만 호출합니다. 거래 조회마다 승인한 사업자 목록과 그 사업자의 계좌 목록에서 입력 ID를 대조하므로 다른 회사의 ID를 임의로 입력해 접근할 수 없습니다. 잘못된 날짜·계좌·페이지 응답은 거부하며 외부 provider 오류나 전체 계좌번호를 그대로 출력하지 않습니다.

## 인증과 운영 설정

Codex에 연결한 Clobe 계정과 웹앱 인증은 별개입니다. Codex MCP OAuth 토큰·클라이언트를 읽거나 복사하지 않습니다. 앱은 Clobe의 공개 OAuth metadata에서 확인한 `https://api.clobe.ai` 인증 서버와 `https://api.clobe.ai/mcp` resource를 사용하고, **Merlin Finance Dashboard**라는 별도 public client를 동적으로 등록합니다. Clobe 로그인과 동의는 처음 연결하거나 재인증할 때 브라우저에서 진행합니다. 요청 범위는 `mcp offline_access`이며 조회 도구만 사용합니다. 앱에서 조회 가능한 사업자는 승인한 Clobe 계정의 접근 권한을 따릅니다.

필요한 서버 환경값은 다음 두 개입니다. 실제 값을 저장소·브라우저·로그에 기록하지 않습니다.

| 환경값 | 설정 |
| --- | --- |
| `CLOBE_TOKEN_ENCRYPTION_KEY` | 암호학적으로 무작위인 32바이트를 표준 base64로 인코딩한 44문자 값 |
| `CLOBE_OAUTH_REDIRECT_URL` | 운영에서는 `https://finance.example.com/api/clobe/callback (자신의 배포 주소로 교체)` |

암호화 키는 유지해야 합니다. 기존 키 없이 변경하면 저장된 연결을 복호화할 수 없습니다. 키 교체·콜백 도메인 변경은 운영자가 별도 재등록·재연결 절차를 준비해야 하며 연결 화면에서 조용히 클라이언트를 바꾸지 않습니다. 로컬 HTTP 콜백은 개발 모드의 localhost/127.0.0.1에서만 허용하고, 운영 DB의 연결을 개발용 콜백으로 대체하지 않습니다.

새 설치는 `supabase/migrations/`의 모든 SQL을 파일명 순서대로 적용합니다. 기존 설치는 자신의 적용 이력을 확인하고 미적용 파일만 실행합니다. OAuth DB 준비·서버 환경값·웹앱 승인·배포 확인은 각각 별도 단계이며 [설치·개발 가이드](DEVELOPMENT.md)를 따릅니다.

## 저장·권한 경계

`private.fd_clobe_connections`는 공유 재무자료의 안정적인 `owner_id`를 연결 식별자로 사용합니다. 기존 앱 관리자는 같은 연결을 조회하고 사용하며, 관리자 변경이나 OAuth 재연결로 재무자료의 소유자와 Auth 사용자를 바꾸지 않습니다. 연결된 Clobe 계정의 개인 이메일은 확인되지 않은 값으로 추정해 표시하지 않습니다.

클라이언트 ID와 OAuth access/refresh token은 AES-256-GCM으로 암호화해 저장합니다. 암호화에는 workspace owner와 자료 종류를 AAD로 묶어 다른 소유자·용도로 복사한 ciphertext의 복호화를 거부합니다. DB에는 암호문만 있고 암호화 키는 앱 서버 환경에 있습니다. service-role 키를 사용하지 않습니다. private 테이블의 직접 조회·쓰기 권한을 제거하고 RLS를 켭니다. 공개 `fd_clobe_auth` RPC는 SECURITY INVOKER이며 private core만 제한된 definer로 실행합니다. 모든 작업은 현재 `auth.uid()`와 기존 관리자·공유 소유자 함수를 다시 검사합니다. RPC에 owner/user ID를 임의로 전달해 다른 연결에 접근할 수 없습니다.

`POST /api/clobe/connect`는 설정된 운영 origin과 동일한 Origin을 요구합니다. Host/forwarded header로 OAuth 콜백을 만들지 않습니다. PKCE S256 verifier와 state는 10분간 암호화된 HttpOnly·SameSite=Lax 쿠키로 보관하고, HTTPS에서는 Secure를 사용합니다. 콜백은 로그인한 관리자·workspace·state·만료를 함께 검사하며 DB의 actor-bound attempt를 토큰 교환 전에 단일 사용으로 소비합니다. 가장 최근 연결 요청만 유효하고 성공·실패 모두 쿠키를 만료시킵니다. 결과는 고정된 `/upload?clobe=connected` 또는 `clobe=error`로만 이동하며 OAuth code나 provider error를 다시 출력하지 않습니다.

refresh token 회전은 90초 lease와 version CAS로 직렬화합니다. refresh 요청 전 `refresh_uncertain`를 DB에 먼저 기록합니다. 네트워크 응답 유실·저장 실패·실행 중단 때 이전 refresh token을 자동 재사용하지 않고 다시 연결하도록 안내합니다. 성공한 토큰 저장만 이 표시를 지우며, 만료된 lease나 다른 관리자의 lease로 저장하지 못합니다.

`GET /api/clobe/status`의 공개 형식은 `{configured, connected, state, accountLabel, connectedAt, expiresAt, updatedAt, error}`입니다. 암호문·토큰·클라이언트 ID·workspace ID·OAuth attempt는 브라우저 응답에 포함되지 않습니다. `getClobeAccessToken(db, ownerId)`는 Node 서버의 조회 코드에서만 사용하며 반환값을 JSON/로그/클라이언트 컴포넌트에 전달하지 않습니다.

# Clobe 거래 분류와 적용

기존 MCP 조회는 잔액·거래를 화면에 보여주는 기능입니다. **거래 불러오기 → 계정과목 분류 → 적용**은 선택한 Clobe 원화 통장의 새 거래를 기존 멀린 자료에 추가하는 별도 흐름입니다. 선택한 모든 통장·페이지가 성공하고 원본 총건수가 일치한 뒤 미리보기를 제공합니다. 일부 다운로드·페이지 오류·cursor 반복·총건수 변화·외화 통장은 저장하지 않습니다. 20,000건 또는 응답 3MiB를 넘거나 조회 시간이 초과되면 기간을 나누어 다시 조회합니다. 버튼은 은행 재수집을 요청하지 않고 Clobe의 마지막 수집 자료를 조회합니다.

Clobe 회사·통장을 멀린의 사업자 계좌에 **직접 확인해 연결**합니다. 이름을 비교해 계좌를 확정하거나 새로운 사업자·계좌를 자동 생성하지 않습니다. 적용한 계좌 연결은 다음 방문에 복원합니다. 이미 가져온 원본이 다른 멀린 계좌에 연결되는 변경은 차단합니다. 거래 적용 전에는 현재 Clobe 회사·계좌 접근 권한과 원화 통화를 다시 검사하며 원본 거래 전체를 재다운로드하지 않습니다.

자동 분류에는 멀린의 기존 사용자 규칙을 사용합니다. Clobe의 분류명은 `source_details.note`에 표시용으로만 보존하며 `raw_gwamok`은 빈 값으로 저장합니다. 계정과목은 사용자가 미리보기의 신규 행에서 고칠 수 있습니다. 기존 거래·기존 수동 분류·메모·날짜·금액·입출금·잔액·업로드 및 이체 연결은 덮어쓰지 않습니다. 명시되지 않은 상대방을 추측하지 않고 Clobe의 원본 거래명·설명·명시된 상대방·메모를 지원되는 `source_details` 필드에 보존합니다.

원본 ID는 별도 `private.fd_clobe_transaction_refs`에 기록합니다. 동일 통장·날짜·금액이어도 원본 시간 또는 잔액이 다르면 서로 다른 정상 거래로 유지합니다. 기존 거래와 일치하는 시간·잔액 또는 명시된 내역의 충분한 근거가 있는 유일 거래는 추가하지 않고 원본 ID만 연결합니다. 불분명한 후보·변경된 원본·서로 다른 원본 ID가 같은 거래를 가리키는 충돌은 보류합니다. 한 계좌·일자에 충돌이 있으면 그 계좌의 해당 일자 전체를 보류하여 일부 거래의 마지막 잔액만 확정된 것처럼 보이지 않게 합니다. 다른 완전한 날짜·계좌의 정상 거래는 명시적인 확인 후 적용할 수 있습니다.

미리보기의 금융 원본은 AES-256-GCM으로 암호화하고 자료 소유자·행위자·미리보기 ID를 AAD에 결합해 private DB에 보관합니다. 미리보기는 2시간 동안 적용할 수 있으며, 만료한 미적용 원본은 같은 관리자가 다음 미리보기를 만들 때 정리합니다. 적용 성공 후 암호문은 비우고 재시도에 필요한 결과만 유지합니다. 브라우저에는 불투명한 미리보기 ID와 표시할 분류 자료만 제공합니다. 적용 요청은 그 ID와 신규 행의 계정과목 ID만 허용합니다. 서버가 원본을 복호화하고 최신 DB에서 중복·충돌을 재검사합니다. 이후 공유 관리자·계좌 잠금·기존 후보 ID·시간·잔액의 해시 비교·원본 참조 고유키·계정과목 소유 검증을 포함한 하나의 RPC에서 원자적으로 저장합니다. 같은 ID·선택의 재시도는 저장 결과를 재사용하며 다른 선택으로 이미 완료된 ID를 재사용하면 409로 차단합니다.

`CLOBE_IMPORT_SIGNING_KEY`는 서버 전용 추가 환경값입니다. 마이그레이션은 `private.fd_clobe_import_verifier`의 singleton에 무작위 32바이트 Base64 키를 생성합니다. 운영 관리자가 DB 연결을 통해 값을 출력 없이 읽고 같은 값을 서버 Secret에 설정합니다. **직접 조회 RPC·클라이언트·로그·마이그레이션·문서에 키를 공개하지 않습니다.** OAuth 암호화 키와 목적을 분리합니다. 공개 INVOKER `fd_clobe_import(text,text,text)`와 제한된 private definer는 exact wire JSON 문자열·action·현재 행위자·공동 자료 소유자에 대한 표준 HMAC-SHA256 증명을 검증합니다. 서명 없는 브라우저 직접 RPC 호출로 미리보기 원본이나 금융값을 위조할 수 없습니다. 모든 private 표는 RLS를 활성화하고 anon/authenticated 직접 권한을 제거합니다. 서비스 역할 키는 사용하지 않습니다.

API: `GET /api/clobe/import`는 이전 계좌 연결을 반환합니다. `POST`의 `action: "preview"`는 `start_date`, `end_date`, `mappings`를 받습니다. `action: "apply"`는 `previewId`, 신규 행의 `choices: [{key, category_id}]`만 받습니다. `category_id: null`은 미분류로 저장하는 명시적 선택입니다. 기존 참조 행의 계정과목은 수정할 수 없습니다. 저장 성공 후 기존 공유 자료 갱신 흐름이 거래내역·미분류 정리·통합분석·가용자금 계획을 함께 재조회합니다. 재조회 실패는 저장 실패와 구분해 안내합니다.

## 카드 청구로 기존 지출 계획 교체

**가용자금 계획 → 카드 청구 동기화**는 결제일·카드별 청구 합계만 조회합니다. 카드 사용처·소유자·전체 카드번호는 반환하지 않으며 마지막 네 자리만 표시합니다. `CARD_BILLING` 수집 상태를 통장 수집 상태와 구분하고 회사별 오류·미수집을 안내합니다. 전체 페이지·총건수·합계가 검증된 미래의 양수 `REGULAR` 청구만 계획 교체에 사용합니다. 선결제·조정·기한 경과·불명확한 자료는 조회만 제공하며, 같은 카드의 해당 결제월에 선결제·조정이 있으면 미납 잔액을 확정할 수 없어 정기 청구도 교체를 차단합니다. 원본이 비었다고 0원으로 만들지 않습니다.

기존에 관리자가 확인한 통장 연결이 한 사업자를 가리키는 경우에만 사업자 선택을 복원합니다. 카드의 출금계좌는 직접 선택합니다. 관리자는 같은 사업자·청구월의 기존 카드대금 계획을 선택하며 수수료·급여·세금·비카드 계획은 교체 대상에서 제외합니다. 적용 직전에 청구 원본을 다시 조회하고 검토한 날짜·금액·종류·그룹이 같아야 저장합니다.

기존 공동 `fd_cash_plan_edits`와 버전 검사 RPC를 재사용합니다. 선택한 기존 항목을 해당 월에 제외하는 변경과 새 청구 일정을 하나의 원자적 저장 요청으로 처리하며, 실패하거나 버전이 충돌하면 일부만 저장하지 않습니다. 과거 계획을 삭제하거나 모든 달에서 제외하지 않습니다. 청구 그룹의 안정적인 UUID로 재동기화 중복을 막고 직접 제외한 청구는 자동 복원하지 않습니다. 내부 연결 정보는 사용자 비고와 분리해 표시하며 비고를 수정해도 원본 연결은 보존합니다. 새 DB 마이그레이션·Secret·OAuth 권한 추가는 필요하지 않습니다.

저장된 청구 일정은 기존 공유 계획 상태를 사용하므로 사업자별 지출표·계좌별 필요자금·필요자금 팝업·달력이 함께 갱신됩니다. 실제 카드 결제·은행 이체·통장 거래·현재 기록 잔액·계정과목은 변경하지 않습니다. 계약 근거는 [Clobe 카드 청구 분류 안내](https://docs.clobe.ai/labelling/card-bill-labeling/)입니다.
## 최신 통장 잔액을 자금계획에 반영

모든 탭 상단과 거래 업로드·가용자금 계획의 **Clobe 최신 동기화**는 기존에 관리자가 확정한 원화 통장 연결 전체를 사용하되 **최근 2개월(지난달 1일~한국시간 오늘)** 거래만 조회합니다. 이번 달·지난달의 신규 거래를 먼저 저장하고, Clobe의 현재 수집 잔액과 계획용 은행 출금을 별도로 저장합니다. 예를 들어 어느 달 14일에 실행하면 지난달 1일부터 그날까지를 조회합니다. 공유 Dataset을 다시 읽어 거래내역·미분류 정리·자금 현황·통합분석·가용자금 계획·달력을 갱신합니다. 신규 거래가 0건이거나 최근 거래 조회 일부가 실패해도 잔액 단계와 화면 갱신을 시도합니다. 은행 재수집을 시작하는 버튼은 아니며 최신 원본이 필요하면 Clobe의 은행 수집 상태를 확인합니다.

같은 브라우저 문서에서는 버튼을 다시 눌러도 진행 중인 작업 하나를 공유하고 메뉴 이동 중에도 이어집니다. 저장 성공과 화면 재조회 실패를 구분하고 재조회만 다시 할 수 있습니다. 다른 문서·관리자의 동시 실행은 서버 원본 ID·버전 검사·원자적 저장으로 중복과 덮어쓰기를 방어합니다. 계획 기간과 편집 내용은 유지합니다. 배포 전에 열어 둔 화면에는 새 기능이 없을 수 있으므로 브라우저를 한 번 새로고침해 최신 화면을 불러옵니다.

최신 동기화는 서버에서 기존 사용자 규칙만 신규 행에 적용하며 규칙이 없으면 미분류로 저장합니다. Clobe 분류를 멀린 계정과목으로 임의 채택하지 않습니다. 기존 거래의 과목·금액·적요·메모·저장 계획을 수정하지 않습니다. **거래 불러오기 → 사용자 계정과목 확인 → 대시보드 적용**은 선택한 기간·통장·신규 과목을 검토하는 수동 경로로 유지하며 더 오래된 기간도 직접 선택할 수 있습니다. 수동 화면의 기본 기간도 최근 2개월입니다. **구글 시트 최신 동기화**는 별도 기능입니다. 잔액만으로 지출을 지급 완료로 판정하지 않습니다.

최신 동기화는 `POST /api/clobe/import`의 `{action:"sync_prepare", month:"YYYY-MM"}`와 `{action:"sync_apply", previewId}`를 최근 두 월에만 순서대로 사용합니다. 서버도 지난달·이번 달 외의 자동 준비를 거부하고, 아직 적용되지 않은 과거 자동 snapshot의 신규 저장을 차단합니다. 이미 저장된 요청은 같은 opaque ID로 결과만 복구할 수 있습니다. 기간·전체 계좌 연결·신규 자동 분류는 서버에서 결정하고 암호화 snapshot에 고정합니다. 자동 적용은 그 snapshot만 받으며 수동 preview와 교차 적용할 수 없습니다. 각 계좌는 성공한 은행 수집 시각까지 전체 페이지를 검증하고 조회 전후 수집 시각이 같아야 합니다. 수집 중·실패·페이지 누락인 통장은 그달의 원본 전체를 폐기하고 계좌별 사유를 표시하며 정상 통장의 거래는 별도로 적용합니다. 같은 회사의 수집 상태가 조회 도중 바뀌면 그 회사의 통장 모두를 제외합니다. 전체 설정 연결과 실제 검증된 연결을 따로 고정하고 적용 시 두 범위를 다시 검사합니다. 검증된 통장이 하나도 없거나 전체 인증에 실패하면 그달을 저장하지 않습니다. 원본 충돌이 있는 계좌·일자 전체는 보류하며 기존 거래·마지막 검증 값은 유지합니다. 일부 계좌·월 실패가 있으면 전체 완료로 표시하지 않습니다. 마지막 잔액 단계와 화면 재조회는 별도로 시도하며 응답을 잃은 적용은 같은 preview ID로만 한 번 재시도해 저장 결과를 복구합니다.

`POST /api/clobe/balance-sync`는 본문 없음 또는 빈 객체만 받습니다. 브라우저에서 잔액·계좌 연결·소유자·조회 도구를 제출할 수 없습니다. 기존 관리자 인증과 앱 Clobe OAuth, 서버 HMAC 서명 키를 재사용합니다. 신규 권한·서비스 역할 키는 필요하지 않습니다. 응답은 `{accounts, synced, unchanged, skipped}`이며 저장 후 공유 자료 조회 실패를 저장 실패와 구분해 화면 재조회만 제공합니다.

`private.fd_clobe_balance_snapshots`는 계좌별 최신 관측값을 저장합니다. 은행 수집 성공·KRW·정확한 정수·수집 시각·현재 계좌 연결을 검증합니다. 더 오래된 응답이나 동일 수집 시각의 상이한 잔액은 기존 값을 유지합니다. 실패·외화·미확인 연결은 건너뛰며 기존 잔액을 0원으로 만들지 않습니다. 공개 INVOKER RPC와 제한된 private 함수는 기존 공동 관리자·자료 소유자 및 용도별 HMAC을 검사합니다. 직접 테이블 권한은 제거하고 RLS를 유지합니다.

공유 Dataset의 선택 필드 `balance_snapshots`는 잔액·근거일·수집 원본 시각·저장 시각과 사업자/계좌 ID만 제공합니다. 시간대가 없는 원본 시각은 그대로 표시하며 비교에만 서울 은행 시각을 사용합니다. 현재 자금계획과 홈·통합분석의 오늘 종료일 잔액은 같은 검증된 관측값을 사용하되, 더 최신인 거래가 있으면 원장을 우선합니다. 과거 종료일은 해당 원장을 사용하고 거래 기반 지출 실적은 유지합니다. 수집 잔액과 저장 거래 잔액이 다르면 남은 지출 확인 안내를 표시합니다.

이 private 관측 표는 기존 public-resource JSON 백업에 포함되지 않습니다. 전체 복구 시 별도로 보존하거나 Clobe 최신 동기화로 다시 수집해야 합니다. 계좌 삭제에는 FK 정리를 따르며 사용자 요청 없는 원장 초기화는 하지 않습니다.
