# Slack 거래 시트 가져오기

## 기본 사용 방식: 필요할 때 수동 반영

기본 설치에서는 시트가 업데이트되면 관리자가 직접 가져옵니다. **거래 업로드 → 최신 동기화** 버튼은 서버에 등록된 모든 통장 시트의 전체 기간을 읽고 신규 거래만 바로 추가합니다. 화면의 사업자 필터나 미리보기에서 선택한 시트에 제한되지 않습니다. 이미 저장된 거래의 모든 값과 계정과목·메모는 유지하며 기존 중복 행도 삭제하지 않습니다. 결과에는 신규 추가·기존 유지·시트 중복·보류 건수를 표시합니다. 페이지를 열거나 시트를 수정하는 것만으로 거래를 바꾸지 않습니다.

기존의 링크 입력·계좌 선택은 **시트 미리보기 → 신규 거래만 추가**로 사용할 수 있습니다. 이 경로도 신규 추가만 허용합니다. 시트의 기존 거래 값을 수정해도 저장된 거래를 덮어쓰지 않으며, 거래 수정은 대시보드에서 직접 수행합니다.

가져온 직후에는 미리보기 상단에 저장 전 상태와 반영 버튼을 표시합니다. 각 거래의 원본 과목과 사이트에서 인식한 과목을 비교할 수 있습니다. 미등록 과목, 단순 `입금`·`출금`처럼 원본부터 세부 분류가 필요한 과목은 구별해 집계합니다. 미등록 원과목 때문에 이미 유효한 기존 분류를 미매핑으로 덮어쓰지 않으며, 원문은 보존합니다. 과목 목록에 없는 이름을 운영/내부이체로 추측해 등록하지 않습니다.

원본 과목이 단순 `입금`·`출금`이면 기존 계좌·입출금별 분류 규칙으로 찾은 세부 과목을 유지합니다. 규칙으로 찾지 못한 일반·빈 과목은 적요·기본·세부내역 전체가 등록된 세부 과목명 하나와 정확히 일치할 때 연결합니다. 자동 분류를 수동 확정으로 바꾸지 않으며, 기존 유효 분류를 보존합니다. 명시 과목이나 규칙이 없는 거래는 미분류로 남깁니다.

신규 거래 판단은 마지막 거래일 이후로 제한하지 않습니다. 전체 기간을 대조하므로 과거 날짜에 새로 추가된 거래도 가져올 수 있습니다. 동일한 원본 복사 행은 반복해서 추가하지 않습니다. 분류만 다른 행을 별도 거래로 추정하지 않으며 같은 날짜라도 금액·시간·잔액·세부내역이 다른 정상 거래는 구별합니다. 기존 거래와 잔액이 다른 반복 거래는 원본 앞뒤 거래의 날짜순서와 잔액 증감이 모두 일치할 때 신규로 가져옵니다.

기존 적요와 시트 기본내역이 다른 거래도, 계좌·날짜·입출금·금액·잔액이 전체 원본과 저장 원장에서 각각 유일하고 명시된 적요·기본내역·세부내역·거래 상대방 중 하나가 정규화 후 완전히 일치하면 기존 거래로 판단할 수 있습니다. 원본 위치가 없는 은행 거래는 이 근거로 **기존 유지** 처리하고 보류 목록에서 제외하며, 저장된 계정과목·수동 분류·메모·원본·내부이체 연결·수수료 배분은 바꾸지 않습니다. 과목명, 일반 채널 단어, 숫자 참조만의 일치와 메모·비고·부분 문자열은 상대방 확인 근거로 사용하지 않습니다.

명시된 거래시간·상대방이 충돌하거나 잔액이 없고 다른 연결 후보가 남으면 계속 보류합니다. 이미 기록된 원본 위치가 다른 기존 거래를 가리키면, 그 거래도 현재 원본의 다른 행에서 금융 값과 명시 내역으로 유일하게 확인될 때만 행 재배치로 인정합니다. 기존 거래가 사라지거나 정정으로 의심되는 경우에는 새 연결을 만들지 않습니다. 이 판정은 신규 추가 전용 가져오기의 건너뛰기에만 적용하며, 신규 행에만 원본 기본·세부내역을 `source_details`로 저장합니다.

입금·출금 중 한 열의 음수는 반대 방향의 양수 거래로 저장해 취소 내역의 현금 증감을 보존하고 원본 부호를 비고에 남깁니다. 양쪽 열에 동시에 금액이 있으면 계속 확인 대상으로 남깁니다. 연·월·일 분리 표에서 일 셀이 숫자 일자만 표시하는 날짜형 셀인 경우 표시된 연·월·일을 읽으며, 전체 날짜로 표시된 모순된 값은 임의 교정하지 않습니다.

자신의 앱 서버의 `FINANCE_SHEET_IMPORT_SOURCE`에 `{"url":"Google Sheet URL","mappings":[{"sheet":"tab name","account_id":"UUID","selected":true}]}` 형태로 원본과 기존 계좌 연결을 설정합니다. 실제 값은 자신의 서버 전용 환경변수에만 두고 소스·테스트에 넣지 않습니다. 로그인한 관리자에게 원본 링크를 미리 채워주며, 같은 원본의 첫 미리보기에는 저장된 계좌 연결을 사용합니다. 다른 링크에는 이 연결을 적용하지 않습니다. 화면에서 명시적으로 바꾼 계좌 선택은 그 가져오기에 우선합니다.

최신 동기화는 POST `/api/sheet-import`의 `action: "sync"`와 실행 UUID를 사용합니다. 원본과 통장 연결은 서버 설정에서만 읽으며 요청으로 다른 URL이나 계좌를 주입할 수 없습니다. 같은 실행 UUID 재시도는 저장된 결과를 반환하고 동시 실행의 충돌은 최신 DB 상태와 다시 비교합니다. 미연결 통장 시트나 누락된 연결은 오류로 알립니다. 정상 신규 거래는 저장하고 모호한 행은 원본 위치·사유와 함께 보류합니다.

보낸·받은 사업자 쌍과 대여·상환 요약 또는 기록ID·상태·버전으로 구성된 비통장 표는 통장 연결 검사에서 제외합니다. 같은 시트에 실제 입금·출금 헤더, 잔액 또는 단일금액의 입출금 구분·부호 근거가 있으면 계속 통장으로 취급합니다. 거래가 0건이거나 날짜·금액 해석에 실패했다는 이유로 통장을 제외하지 않으므로 실제 빈 통장과 오류가 있는 통장도 계좌 연결을 확인해야 합니다.

저장 응답 후 공유 재무자료를 다시 조회합니다. 업로드 화면을 떠나도 이 갱신은 계속하며, 가져오기 기록 조회가 느려도 잔액 갱신을 지연시키지 않습니다. 신규 거래가 0건인 경우도 최신 DB 자료를 읽습니다. 저장 완료와 화면 재조회 실패는 구분해서 안내하며, 재조회만 실패했을 때는 **자료 새로고침**을 사용합니다. 가용자금 계획의 **현재 기록 잔액**은 새 자료를 반영하고, 저장된 계획 기간과 계획 시작 전 잔액을 사용하는 예산 계산은 유지합니다.

수동 가져오기는 기존 관리자 인증과 권한 검사를 사용합니다. 자동 실행용 토큰·Vault·Cron은 기본 수동 경로에 필요하지 않습니다. 아래 예약 기능은 설치자가 별도로 구성할 수 있는 선택 기능이며 기존 원본 과목 변경을 반영할 수 있어 기본 신규 추가 정책과 다릅니다. 구성 전 preview와 변경 범위를 검증합니다.

## 선택 기능: 예약 자동 연동 구조

```text
Slack에 통장 Excel 업로드
  → 통장내역 자동화 봇: 은행 형식 파싱·계정과목 규칙 적용
  → 기존 Google Sheets의 사업자·계좌별 탭에 기록
  → Supabase Cron이 5분마다 자신의 앱 /api/sheet-sync 호출
  → 등록된 시트·계좌만 읽고 기존 거래와 대조
  → Supabase 공동 재무자료에 신규·변경 거래 반영
  → 멀린 대시보드에서 조회
```

은행 형식을 파싱해 Google Sheets에 기록하는 외부 봇은 설치자가 별도로 준비합니다. 이 저장소는 해당 봇·Slack 인증·계정별 설정을 포함하지 않습니다. 카드 사용 내역은 통장 입출금과 구분합니다.

은행 시트 열은 `연도 / 월 / 일 / 과목 / 기본내역 / 세부내역 / 입금 / 출금 / 세금계산서 유무 / 비고 / 잔액`입니다. 기존 파일·링크 업로드와 같은 파서와 중복 판단을 사용합니다. 봇 코드와 Slack 인증을 바꾸거나 Slack 메시지를 보내지 않습니다. 봇이 어느 PC에서 실행되든 시트가 갱신되면 서버에서 읽습니다.

## 사용자 화면

거래 업로드의 Google 스프레드시트 영역에 원본 링크, 자동 연동 상태, 마지막 실행 시각, 반영 건수와 오류가 표시됩니다. **지금 동기화**는 로그인한 관리자에게만 허용됩니다. 브라우저를 닫아도 Supabase의 예약 실행이 작동합니다. 화면에 이미 열린 재무자료는 새로고침하면 최신 결과가 보입니다.

같은 거래는 반복해서 추가하지 않습니다. 계정과목과 기본·세부내역은 시트에서 읽고 `source_details`에 원본 내역을 보존합니다. 원본이 바뀌지 않은 거래는 다시 덮어쓰지 않아 대시보드에서 직접 수정한 분류를 유지합니다. 시트의 실제 계정과목이 바뀌면 해당 거래에 반영합니다.

예약 실행은 먼저 작은 상태 정보와 시트 내용의 해시를 비교합니다. 시트가 그대로면 전체 재무자료를 DB에서 가져오지 않고 확인 시각만 갱신합니다. **지금 동기화**는 시트 변경 여부와 관계없이 현재 DB와 다시 대조하므로, 관리자가 보류 원인을 정리한 뒤 재시도할 때 사용할 수 있습니다.

잔액·거래시간으로 구분할 수 없는 반복 거래, 메모·내부이체 연결과 충돌하는 변경, 기존 거래 삭제가 필요한 중복 정리는 보류합니다. 정상 거래는 계속 반영합니다. 기존 중복 정리는 기존 링크 가져오기에서 검토합니다.

은행 시트에는 고정 거래 ID가 없습니다. 이전에 반영한 행이 없어지거나 날짜·금액·기본내역이 바뀌면 새 거래로 잘못 추가하지 않도록 자동 실행을 중단합니다. 기존 링크 가져오기에서 변경을 대조·정리한 다음 담당 개발자가 자동 연동 기준을 재설정합니다. 계정과목 변경이나 행 재정렬만으로는 중단하지 않습니다.

## 권한과 비밀값

새 사용자 계정이나 Supabase service-role 키를 사용하지 않습니다. 자동 연동용 32바이트 무작위 토큰을 서버 전용 환경변수 `FINANCE_SHEET_SYNC_TOKEN`에 보관하고, DB의 비공개 등록부에는 SHA-256 해시만 저장합니다. 예약 호출용 원문은 Supabase Vault에 보관합니다. 토큰은 브라우저·소스·로그·문서에 출력하지 않습니다.

`private.fd_sheet_sync_sources`에 원본 URL, 자료 소유자, 활성 관리자, 시트·계좌 연결, 처리한 원본 해시와 실행 결과를 기록합니다. 연결 해제 또는 설정 관리자의 권한 해제 시 자동 실행 권한도 사라집니다. 토큰으로 임의의 소유자·계좌·원본 URL을 지정할 수 없습니다. 공개 RPC는 토큰을 확인한 다음 등록 범위만 읽거나 반영합니다. 일반 관리자 경로는 기존 로그인·관리자 확인을 유지합니다.

비공개 병합 함수는 계좌 잠금, 기존 행 일치 확인, 실행 ID, 감사 기록을 유지합니다. 처리한 원본 해시는 DB 반영과 함께 저장하고 이전 해시와 비교해, 늦게 끝난 실행이 최신 상태를 되돌리지 못하도록 합니다. 자동 실행의 감사 기록은 사람의 사용자 ID를 사칭하지 않습니다.

권한을 검사하는 구현은 `private` 스키마에 두고 공개 RPC는 `SECURITY INVOKER`로 해당 구현만 호출합니다. 경량 상태 조회도 동일한 토큰·활성 관리자 검사를 거치며 거래 원문은 반환하지 않습니다. 원본 URL이나 계좌 연결을 변경하면 저장된 원본 해시를 초기화해 다음 실행에서 다시 대조합니다.

## 선택 예약 기능의 설치 순서

1. 자신의 Supabase에 전체 마이그레이션을 파일명 순서대로 적용합니다. 기존 설치에서는 적용 이력을 확인하고 미적용 파일만 실행합니다.
2. 자신의 원본 시트와 앱의 실제 계좌 UUID를 확인해 `private.fd_sheet_sync_sources`의 소유자·활성 관리자·시트·계좌 연결을 신뢰된 DB 연결에서 구성합니다. 새 계좌를 추측하지 않습니다.
3. 암호학적으로 무작위인 32바이트를 64자리 lowercase hex로 만든 토큰을 서버 전용 `FINANCE_SHEET_SYNC_TOKEN`에, SHA-256 해시를 비공개 등록부에 설정합니다. 같은 토큰 원문은 자신의 Supabase Vault의 `merlin_finance_sheet_sync`에 보관합니다. 토큰을 SQL 파일·브라우저·로그에 쓰지 않습니다.
4. Vault의 `merlin_finance_sheet_sync_url`에 자신의 HTTPS `https://finance.example.com/api/sheet-sync` 주소를 저장합니다. 예시 도메인을 실제 앱 주소로 교체합니다. Preview에는 운영 자동 반영 토큰을 넣지 않습니다.
5. 서버와 DB 설정 후 `POST /api/sheet-sync`의 `action: "preview"`로 범위·합계·보류를 검토합니다. 토큰 인증 경로는 `Authorization: Bearer <server-only-token>`을 사용하며 브라우저에 토큰을 전달하지 않습니다. 미리보기는 거래·처리 해시·상태를 쓰지 않습니다.
6. 최초 반영과 동일 실행 재시도의 중복 방지를 자신의 테스트 자료로 확인합니다. `supabase/operations/schedule_sheet_sync.sql`을 검토해 자신의 DB에서 실행해야 Cron이 활성화됩니다. SQL은 Vault에서 URL·토큰을 읽습니다.

구성과 검증 결과는 설치자의 비공개 운영 기록에 남깁니다. 실제 거래·인증값을 공개 issue·로그에 남기지 않습니다. 익명 호출에 등록 범위 외 자료를 허용하거나 일반 관리자 인증을 우회하지 않습니다.

## 중지와 복구

DB 담당자는 해당 원본의 `enabled=false`로 자동 실행을 중지할 수 있습니다. 예약 작업도 필요하면 비활성화합니다. 재연결 시 기존 자료·소유자·관리자 명부를 삭제하지 않습니다. 기준 해시 재설정은 원본 변경을 기존 거래와 대조한 뒤에만 수행합니다. 네트워크 실패는 다음 실행에서 재시도하며, 같은 실행 ID는 한 번만 반영됩니다.

원본 제한은 내보내기 4MB, 거래 시트 40개, 자동 처리 거래 20,000건입니다. 시트 추가·이름 변경은 연결 설정 확인이 필요합니다. 읽기 권한을 잃으면 실패 상태를 표시하고 기존 거래를 유지합니다.
