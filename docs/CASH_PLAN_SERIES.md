# 월 고정비와 유한 할부 계획

가용자금 계획의 **사업자별 지출 계획표 아래 → 월별 고정비·부가세 할부**는 모든 사업자의 저장한 반복 예산을 보여줍니다. 등록 전 사업자도 각 월의 **항목 추가**로 직접 등록할 수 있으며 등록 전을 0원 예산 확정으로 표시하지 않습니다. 시작월과 종료월을 포함해 계산하며, 종료월 다음 달부터 해당 할부는 합계에서 빠집니다. 종료월이 없는 고정비는 계속 표시됩니다. 마지막 회차처럼 금액이 다른 달은 월별 금액으로 지정할 수 있습니다.

월 제목을 누르면 기존 지출계획표에서 그 달 전체를 조회합니다. 요약의 월 이동만으로 기존 조회기간이 바뀌지는 않습니다. 월 전체 예산과 실제 출금·남은 지출은 구분하며, 요약 합계를 잔액에서 다시 차감하지 않습니다. 다른 변동 지출은 기존 계획표에서 확인합니다.

**기본 고정비 금액의 내역보기**를 누르면 해당 사업자·월의 구성 항목이 팝업으로 열립니다. 분류별 소계와 개별 항목의 계획금액·예정일·출금계좌·메모를 확인하고, **수정**에서 금액과 지급일 등을 변경할 수 있습니다. 수정·추가·삭제할 때 **이번 달만 / 이번 달부터 계속**을 선택합니다. 저장 성공 후 팝업 합계·월별 필요자금·지출계획표를 같은 공동 설정으로 다시 계산합니다.

**카드대금** 분류는 관리자가 직접 확인한 결제금액과 결제일을 입력하는 일반 계획입니다. 기본 적용 범위는 **이번 달만**이며, 반복하려면 직접 **이번 달부터 계속**을 선택합니다. 이 금액은 해당 사업자의 월 요약과 지출계획에 한 번씩 연결됩니다. 자동 카드 청구 연동을 새로 실행하지 않으며 기존 청구·구독료·할부와의 관계를 임의로 추정해 제거하지 않습니다. 입력할 때 같은 금액이 기존 계획에 이미 포함되어 있는지 확인합니다.

**이번 달만**은 기존 월별 수정·추가·제외를 저장합니다. **이번 달부터 계속**은 선택한 월을 시작으로 반복 금액·지급일·계좌·메모를 저장하거나 계속 제외합니다. 이전 월의 계획은 보존합니다. 지급일은 매월 같은 일자를 사용하고 그 날짜가 없는 달에는 말일을 사용합니다. 빈 날짜는 날짜 미정 예산입니다. 기존에 별도로 저장한 미래 월의 예외는 유지하며, 제외 설정은 포함 설정보다 우선합니다. 계속 제외한 항목은 이후 월별 포함값이나 동기화로 다시 살아나지 않습니다. 실제 거래·통장 잔액·출금 확인·유한 할부의 종료월은 변경하지 않습니다.

해당 월 또는 전체 기간에서 제외한 항목은 별도 목록에 표시하며 포함 합계에 더하지 않습니다. 기존에 제외한 급여는 다른 항목을 편집하거나 추가해도 복원되지 않습니다. 팝업에서는 제외 항목을 조회만 합니다. 월 한정 제외의 명시적 복원은 기존 **계획 편집 → 제외**에서 진행하며 계속 제외에는 적용하지 않습니다. 상세 조회만으로 기존 계획 조회기간을 바꾸지 않습니다. 분류는 일정에 명시된 근거를 사용하며 확인되지 않은 항목의 용도를 추측하지 않습니다.

기존 **계획 편집**의 금액·계좌·일자·제외 설정과 출금 확인은 해당 월의 반복 예산보다 우선합니다. 날짜 또는 계좌가 확인되지 않은 예산은 날짜·계좌 미지정으로 유지하며 임의의 납부일이나 통장에 배분하지 않습니다. 과거에 종료된 회차를 실제 납부 완료로 판정하지 않습니다.

지출계획표에서 저장한 반복 추정 항목도 해당 월의 고정비로 명시적으로 연결할 수 있습니다. 이 경우 원본 사업자·계좌·거래 식별자와 월별 수정의 ID를 유지하며, 같은 지출을 새 수동 항목으로 복사하지 않습니다. 연결한 달의 계획금액·지급일·계좌·제외 상태를 고정비 탭에서 함께 사용하고, 다른 달의 추정이나 출금 실적 계산은 바꾸지 않습니다. 고정비 합계는 월 전체 계획금액이며 이미 출금한 금액이나 남은 예산과 구분합니다.

## 개발과 저장

`fd_cash_plan_series`는 공동 소유자 범위의 예산만 저장합니다. 기존 추정과 연결되는 일정은 정확한 `source_type`과 `source_key`를 사용해 같은 월 원본을 대체하고, 별도 할부는 고유한 manual 식별자로 전개합니다. 제목이나 과목이 비슷하다는 이유로 다른 지출을 자동 제거하지 않습니다. 시작 전의 기존 계획과 다른 사업자 자료는 보존합니다.

`fd_read_cash_plan_series()`는 관리자 인증과 RLS를 유지하는 INVOKER 함수입니다. `fd_read_finance_dataset()` 응답에 함께 포함해 추가 조회를 만들지 않습니다. 자료가 누락되거나 잘못되면 로더가 오류를 표시하며 0원 예산으로 처리하지 않습니다. 전체 JSON 백업에도 일정을 포함합니다.

반복 계획은 두 산정 기준의 공통 원본입니다. 기존 월별 수정·제외·확인은 `fd_cash_plan_edits`에 저장합니다. 종료 뒤의 월 수정이 이미 있더라도 종료한 일정이 다시 살아나지 않습니다. 기존 거래나 통장 잔액은 생성·수정하지 않습니다.

월 한정 편집은 기존 관리자 인증·동일 출처 검사·버전 충돌 검사가 있는 `/api/cash-plan`과 저장 RPC를 사용합니다. 계속 적용은 `/api/cash-plan/fixed-costs`에서 반복 원본의 버전과 선택 월의 수정 버전을 함께 검사하고 한 트랜잭션에서 저장합니다. 적용 시작월별 이력은 `fd_cash_plan_series_revisions`에 보관하며 이후 포함 이력을 대체할 때도 취소 상태로 남깁니다. 이전에 계속 제외한 이력은 취소하지 않습니다. 새 조회 자료는 기존 엄격한 series 형식을 확장하지 않고 별도 `cash_plan_series_revisions` 키로 반환합니다.

변경한 항목만 전송하고 기존 출금 확인 메타데이터는 보존합니다. 새 월별 고정비는 고유 manual 원본과 내부 고정비 식별자를 사용하며 일반 메모 편집 후에도 식별자를 보존합니다. 월별 항목을 매월 반복으로 전환할 때는 같은 원본 식별자를 재사용하고 전환 이전의 월별 항목도 보존합니다. 요약과 지출계획표에 같은 항목을 두 번 추가하지 않습니다. 실패·충돌 시 입력값을 유지하고 최신 자료 확인을 안내합니다. 저장 응답의 반복 계획·이력·월별 수정을 공유 화면 상태에 함께 반영하고, 저장보다 오래된 조회가 나중에 도착해도 최신 버전을 덮어쓰지 않습니다.

## 설치와 검증

새 설치에는 `supabase/migrations/20261028031740_cash_plan_series.sql`과 `20261028065402_cash_plan_series_revisions.sql`을 포함한 모든 마이그레이션을 파일명 순서대로 적용한다. 기존 설치는 자신의 적용 이력을 확인하여 미적용 파일만 실행한다.

합성 테스트는 월별·계속 적용, 이전 월 보존, 유한 할부 종료, 제외 우선순위, CAS 충돌·롤백과 기존 원장 불변을 검사한다. 실제 금액·개인카드 정보·운영 입력자료는 공개 문서와 fixture에 넣지 않는다.
